# F10d · 访问历史 · 目录路径统一带尾分隔符

**性质**：对 `F10c-访问历史-step2-实施计划.md` §2.1 数据契约、§3.1 / §3.3 实现的修订。基线为 F10c 已落地的代码（`internal/finder/history.go`）。

**起因**：finder 中面包屑、子目录列表显示目录时都以 `/` 结尾，唯独 history 列表显示的目录路径没有尾分隔符，风格不一致。

**范围**：把「目录路径带尾分隔符」确立为 history 数据的存储规范，从源头（`history.json`）保证。显示层与 `truncateLeftPath` 不做任何特殊处理。

---

## 1. 问题

F10c 落地后的现状：

- `recordDirHistory` 对传入目录执行 `filepath.Clean`，结果不带尾分隔符（根目录 `/` 除外）。
- `history.json` 元素形如 `/home/user/project`，无尾 `/`。
- `historyList.Display` 直接把这个串交给 `truncateLeftPath`。
- `truncateLeftPath` 的契约本就要求 path 以分隔符结尾；其早返回分支 `stringWidth(path) <= maxW` 会原样返回 path。于是：
    - 路径短、能完整放下 → 显示无尾 `/`；
    - 路径长、被左截断 → 尾段被拼上 `/`。
- 同一列表里短长两种条目尾部分隔符有无不一，与面包屑 / 子目录列表（恒带 `/`）不一致；同时也违背了 `truncateLeftPath` 的前置条件。

## 2. 决策

目录路径在 `history.json` 中统一以路径分隔符结尾。`truncateLeftPath` 是左截断，只动头部，字符串尾部的分隔符与截断无关——只要源串带尾分隔符，无论是否截断，显示都恒带尾分隔符。因此只改数据源，不改显示层。

三条规则：

1. **写入**：`recordDirHistory` 不做任何「智能补全」——它不知道传入的字符串是目录还是文件。调用方 `fileList` 在调用前自行保证目录路径以分隔符结尾。`history.json` 中每条目录都带尾分隔符。
2. **读取**：`readDirHistory` 只接受以分隔符结尾的条目；缺尾分隔符的条目（旧版残留或外部手改）一律忽略，当它不存在。不补、不迁移。
3. **激活**：`historyList.activate` 对 cursor 路径 stat，确认是目录则切换；否则（不存在、已变成文件、stat 失败）一律 `removeCurrent`。不再保留「stat 失败时保留条目」的分支。

规则 2 保证了读取后内存里的条目全是带尾分隔符的规范形，去重比较 `d == dir`（两边都带分隔符）自然成立；旧的无尾分隔符条目在下次读取时消失，下次任意写入后从文件中清除。

规则 3 把「不是目录」与「不存在」合并为同一处理。带尾分隔符的路径 stat 真目录正常；已变成文件时返回的错误（`ENOTDIR` 一类，`IsNotExist` 为假）在旧的 3-case switch 里会落到「保留」分支，违背「不是目录就删」的意图。实测：

```
Stat("realdir/")  → err=false, IsDir=true      （真目录，正常）
Stat("realfile/") → err=true,  IsNotExist=false （变成文件，会被旧 switch 误判为保留）
Stat("nope/")     → err=true,  IsNotExist=true  （不存在）
```

改成「确认是目录才进，否则删」后，`ENOTDIR` 这类错误自然归入删除，无需为尾分隔符做任何特例处理。

**代价**：原 F10c §3.3 中 `default: return`（权限 / IO 临时错误保留条目）的行为取消。对目录历史无实质影响——无法 stat 的目录本来也无法切入，从列表删掉无害，用户重新导航时会重新记录。

## 3. 改动步骤

### 3.1 `fileList` 调用 `recordDirHistory` 前补尾分隔符

`recordDirHistory` 不假定传入的是目录还是文件，不做路径清理和补分隔符。调用方 `fileList` 在选文件时（`filelist.go` `case rowFile`）自行保证路径以分隔符结尾：

```go
// filelist.go — 调用 recordDirHistory 前，currentDir 已由 chdirTo 的 Clean 保证干净
recordDirHistory(l.currentDir + string(filepath.Separator))
```

`l.currentDir` 在 `chdirTo` 中已过 `filepath.Clean`，路径是标准形（无尾缀 `.`/`..`、无多余分隔符），追加 `/` 即可。

`recordDirHistory` 本身不再引入 `filepath.Clean`。

### 3.2 `readDirHistory` 过滤无尾分隔符的条目

反序列化后只保留以分隔符结尾的元素，返回新 slice：

```go
var raw []string
if err := json.Unmarshal(data, &raw); err != nil {
    _ = os.Remove(path)
    return []string{}
}
dirs := make([]string, 0, len(raw))
for _, d := range raw {
    if len(d) > 0 && d[len(d)-1] == filepath.Separator {
        dirs = append(dirs, d)
    }
}
return dirs
```

`len(d) > 0` 守卫空串（JSON 里可能出现的 `""`），空串不可能是合法目录路径，自然被过滤。`make` 返回非 nil 空 slice，原 `if dirs == nil` 守卫不再需要。

### 3.3 `historyList.activate` 收敛为「确认目录或删除」

替换原 3-case switch：

```go
dir := h.dirs[h.cursor]
info, err := os.Stat(dir)
if err == nil && info.IsDir() {
    h.fm.ActivateFromHistory(dir)
    return
}
h.removeCurrent()
```

`dir` 带尾分隔符；`ActivateFromHistory` → `chdirTo` 首行 `filepath.Clean`，下游 `currentDir` 仍是 clean 形态，不受影响。带尾分隔符的真目录 stat 正常（见 §2 实测），无需任何特判。

函数注释改为：

```go
// activate 对当前 cursor 路径 stat。有效目录 → Session.ActivateFromHistory；
// 其余（不存在 / 已不是目录 / stat 失败）一律从列表与 history.json 中移除。
```

## 4. 对 F10c 契约的修订

- §2.1 数据示例改为带尾分隔符：

```json
[
    "/home/user/project/internal/finder/",
    "/home/user/project/docs/"
]
```

  并补充规则：每个元素必须以路径分隔符结尾；读取时缺尾分隔符的条目视为不存在。

- §3.1 `recordDirHistory` 不再负责补尾分隔符；改为 `fileList` 调用前在 `l.currentDir` 后追加分隔符。
- §3.2 `readDirHistory` 过滤规则同前，无改动。
- §3.3「目录激活流程」的 switch 收敛为本文 §3.3 的 if 形式；`default: return` 分支取消。

## 5. 测试

`internal/finder/history_test.go` 受影响——读取现会过滤无尾分隔符条目，凡直接写 `["/a","/b"]` 再读的用例都会读到空；同时 `recordDirHistory` 不再补尾分隔符，直接传 `t.TempDir()` 的用例需改为传 `t.TempDir() + sep`：

- `TestHistoryRead_ValidFile`：输入与期望改为 `["/a/","/b/"]`。
- `TestHistoryRead_ReturnsIndependentSlice`：输入改为 `["/a/","/b/"]`，二次读取期望 `"/a/"`。
- `TestRecord_FirstWritesDirectory`：`recordDirHistory(dir)` 改为 `recordDirHistory(dir + sep)`，期望 `dir + sep`。
- `TestRecord_DedupesAndMovesToHead`：`recordDirHistory(a/b/c)` 改为 `recordDirHistory(a/b/c + sep)`，`want` 三项各加 `sep`。
- `TestRecord_TruncatesToMaxEntries`：`recordDirHistory(d)` 改为 `recordDirHistory(d + sep)`，比较项各加 `sep`。
- `TestRecord_CleansCleanDirPath`：**删除**。`recordDirHistory` 不再清理路径，此测试已无意义。

不受影响：

- `TestRecord_DoesNotPolluteUserConfig`：子串匹配，`Abs(d)` 仍是带尾分隔符串的子串。
- `TestRecord_EmptyPathDoesNothing`。
- removeCurrent 系列（`newTestHistory` 直注 dirs、直接 `json.Unmarshal` 校验，不经 `readDirHistory`；测的是切片操作与写回机制，与尾分隔符策略无关）。
- `internal/finder/session_test.go`：像素用例只校验 history 分隔线 / label / 交点，不校验路径内容；`TestSession_ActivateFromHistory` 直传 `target` 调 `ActivateFromHistory`，不经 read / record。

## 7. 验收

- 访问若干目录后，`history.json` 每个元素都以分隔符结尾。
- finder 中 history 列表每条目录显示都以 `/` 结尾，与面包屑一致。
- 手动改坏 `history.json`（去掉某条尾分隔符）后重启 finder，该条不出现；其余正常条目不受影响。
- 激活一条已删除或已变成文件的目录，该条从列表与 `history.json` 中消失。
- `make build` 通过，`go test ./internal/finder/` 通过。
